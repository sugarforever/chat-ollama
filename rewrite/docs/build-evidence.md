Tests SIGKILL the HTTP child after admission, retry the original receipt after restart, and compare completed transcript after another restart. Unknown and malformed IDs do not create session files.

Real streaming and error HTTP fixtures prove committed partial text, cancelling, persisted failure after reopen, and omission of provider secret errors. ## Task 3 authentication and provider settings (2026-10-31)

- adapter-node 5.5.7 derives HTTPS when neither ORIGIN nor a protocol header is configured. Direct HTTP deployments must set their exact `ORIGIN`; the real HTTP fixture sets a private trusted HTTP scheme header itself. This preserves strict Origin validation and HTTPS Secure cookies without trusting arbitrary client forwarding headers.
- pi-durable 1.4.0 `Session.configure` takes `AgentChange` directly (`{model:{provider,modelId}}`). Replacing the configured provider in the existing models registry and configuring the root before admission applies changed endpoint/model/key to later runs. Keep the previous endpoint registry and server-side saved snapshot during running/cancelling and resumed work.
- App settings/session token digests use a separate `DATA_DIR/app.sqlite`; no pi-owned schema is modified. `sessions/:id.endpoint.json` records server-only credential-bearing effective run configuration (0600). The process-global startup singleton still joins independently bundled bootstrap/routes.
- New auth/settings real-HTTP tests exercise endpoint requests through real pi, redaction, secret preservation, HTTP URL validation, logout/expiry, rate limiting, central API/SSE/source/page access, and same-origin mutation rejection. Restart during an active run after a settings edit keeps the original endpoint; a later run uses the edited endpoint. Settings edits also apply after a failed upstream run.
- Shared `build/` output must not be rebuilt concurrently with HTTP tests. Both HTTP suites build in beforeAll; Vitest fileParallelism is disabled to prevent one suite deleting the other's running server bundle. A future test preflight can build once instead.

## Task 4 MCP tools (2026-10-31)

- Official MCP SDK 1.25.3 implements stdio and Streamable HTTP, discovery pagination, argument/result translation, explicit environment and headers, and client cleanup. Actual SDK fixture servers exercise both transports. TypeBox wraps discovered JSON Schema for native pi argument validation; names use a deterministic digest of `[server ID, original tool name]` within provider limits. Every MCP tool is replay-unsafe regardless of annotations.
- Pi 1.4.0 tool execution returns `output`, not `content`; a real fixture execution test caught and corrected this. Chord cancellation is `context.abortSignal`, passed to the SDK request options; a held real MCP action proves cancellation settles the request while retaining uncertainty.
- A small app-owned SQLite sidecar persists an inflight marker before the external call. A returned response only changes it to returned; the marker clears only when the committed pi view includes the matching call's result. Restart converts retained markers to uncertainty. The native unsafe replay produces its interrupted result; a GenerationTask beforeRequest hook prevents any follow-on inference while uncertainty exists, and every MCP execute checks the same barrier. No general approval engine or custom replay runner is added.
- The process-crash fixture records an external effect, then waits without returning. SIGKILL/reopen proves exactly one recorded effect, zero additional model requests before acknowledgement, a native interrupted tool entry, visible uncertainty, blocked new input, and a subsequent model request after deliberate acknowledgement. A connection-loss fixture separately proves uncertainty and blocked second dispatch. A focused marker test covers unrelated commits, matching commits, and the returned-response/native-commit crash gap.
- Discovery manifests and server-only configuration snapshots keep active runs stable across restart and allow offline recovery without reconnecting merely to resolve registered tools. Later inputs discover current configuration. Unavailable initial discovery returns a sanitized actionable 502 and does not make global settings inaccessible on startup. Headers/environment remain absent from public settings responses; mutation routes use the existing central authentication/origin gate.
- An initial fixture run failed because zod was only transitive; it is now a pinned direct dependency. An initial `pnpm test -- tests/mcp.spec.ts` invocation selected the full suite under this pnpm/Vitest combination; targeted verification uses `pnpm exec vitest run ...`. All final checks use Node 24; existing ancestor Nuxt/base/node:sqlite build warnings remain visible.

## Task 5 knowledge ingestion and retrieval (2026-10-31)

- Application-owned SQLite tables store named collections, generated document/source IDs, document state and normalized Float32 vectors. Generated private local files retain uploads; no pi schema, legacy database or external search service is used. A single persisted-queue pump batches at most 32 embedding inputs, admits at most 100 pending documents, and retries indexing markers after process restart. A real child-process SIGKILL during a held HTTP embedding request proves recovery and searchable completion without resubmission.
- Pinned PDF.js 5.4.296 extracts text and page numbers from text PDFs. UTF-8 Markdown/plain text is accepted. File uploads are limited to 10 MiB (multipart reading is independently bounded), text to 2 million characters and PDFs to 1000 pages. Paragraph/sentence-aware chunks are at most 1200 characters with 150-character overlap. Real text and image-only PDF fixtures prove page references and the explicit no-OCR failure.
- Independent embedding endpoint/model/key settings produce a private configuration fingerprint. Changed configurations require explicit collection reindexing. Replacement generations publish atomically only after all documents succeed with consistent finite/nonzero dimensions; failed replacement staging is discarded. Stable passage source IDs survive embedding-only reindexing. Query vectors and batches are validated, including reordered response indices, mixed dimensions and zero vectors. Upstream response errors never expose fixture credentials.
- `search_knowledge` is replay-safe, read-only, registered by startup only for selected collection IDs, and forwards native Stop cancellation to embedding requests. A real built SvelteKit HTTP/pi run invokes it and sends selected document sources back to the model while excluding another collection. API/source routes use the existing central login/origin gate. JSON source excerpts are inert and deleted documents/collections invalidate source lookup and remove files/chunks.
- SQLite cosine scanning runs in a worker thread with a row iterator and bounded top-k, at most two active searches. The generated scale test stores 100,000 chunks × 384 dimensions and runs a native pi chat concurrently. On Apple M3, 8 logical CPUs, 24 GiB RAM, macOS arm64, Node 24.22.2: full-suite measurement was 192 ms end-to-end search (including local HTTP query embedding and worker startup), 6 ms concurrent native chat, 6 ms maximum main-loop timer gap; process RSS 157→214 MiB (+57 MiB). A separate focused run measured 194 ms and the same +57 MiB. These are local development observations, not a provider-latency guarantee. The sub-two-second target passed, so an embedded vector index was unnecessary.
- The local HTTP embedding fixture uses deterministic multilingual semantic axes. It proves protocol, batching, cross-language plumbing, isolation and persistence, not trained-model semantic quality. The scale fixture uses generated 384-dimensional vectors and measures CPU/storage/responsiveness rather than retrieval relevance.
- Test-first evidence: initial knowledge service stub failed all four initial behavior tests; built knowledge API first failed authenticated listing with 404; Stop forwarding first returned `still waiting` for a cancelled request. The benchmark initially exposed a test-harness bug: `session.snapshot()` is asynchronous; awaiting its status fixed premature second admission. The same check caught the missing awaits and source/tool result typing. No runtime busy-admission behavior was weakened.
- Final Task 5 serial Node 24 validation: `pnpm test` passed 11 files / 47 tests (45.60s); `pnpm check` reported zero errors/warnings; `pnpm build` completed Vite, adapter-node and bootstrap esbuild (48.4 kB); `git diff --check` was clean.
