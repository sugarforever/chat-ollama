---
title: ChatOllama Agent Runtime 的工作区写入工具
date: 2026-09-09
---

`ChatOllama Agent Runtime` 已经能在 workspace root 内读取和检索文件。这次我继续补上 `write_file` 与 `edit_file`，让模型可以创建文本文件、完整覆盖文件，以及完成可验证的精确替换和批量替换。

写文件带来的问题不只是多调用一个文件系统 API。路径可能在检查之后发生变化，写入可能中途失败，同一个文件也可能被多个工具调用同时修改。我会利用这次实现梳理这些边界怎样落到代码和测试里，期望对大家有所帮助。

## 写入仍然从 workspace root 开始

两个新工具复用读取工具已经建立的 workspace root 语义。模型只能提供相对路径，绝对路径、任何 `..` 路径分量和相邻目录前缀混淆都会先被拒绝。

新文件的目标尚不存在，不能直接对目标调用 `realpath`。Runtime 会从 workspace root 开始逐段检查父目录：已有目录需要确认真实路径仍在工作区内，缺失目录则逐级创建，并在每一步创建后重新检查。这样不会让递归创建沿着一个指向工作区外部的符号链接继续写入。

真正提交内容之前，Runtime 还会重新取得父目录的真实路径，并再次检查已有目标。这个检查离原子替换很近，能够识别检查期间发生的父路径变化。它不是针对同一用户下恶意进程的操作系统沙箱；这一层解决的是 Runtime 对不可信模型输入应承担的路径约束。

## 临时文件与原子替换

`write_file` 不会直接截断目标文件。Runtime 会在已经验证过的目标目录里创建独占临时文件，写入完整内容并同步到文件系统，然后通过 `rename` 原子替换目标。

如果写入、同步、写前校验或替换失败，临时文件会被清理，原文件保持不变。测试通过注入一次确定性的 `rename` 失败来验证这件事：工具返回稳定的 `TOOL_FAILED`，原内容没有变化，目录里也没有残留临时文件。

单次结果内容上限是 1,048,576 字节。`write_file` 在接触文件系统前检查完整内容，`edit_file` 则同时限制原文件和替换后的结果，避免一次工具调用读写无界文本。

## 内容版本与条件写入

成功的 `read_file`、`write_file` 和 `edit_file` 结果都会返回基于完整文件内容计算的 `sha256:<hex>` 版本。模型可以把这个版本作为 `expectedVersion` 传给 `write_file` 或 `edit_file`，要求只有文件仍未变化时才提交；版本过期会返回 `VERSION_CONFLICT`，并保持文件不变。不提供 `expectedVersion` 时，仍保留无条件写入行为。

## 精确替换只接受严格答案

`edit_file` 兼容旧的单个 `oldText`/`newText` 输入，也接受最多 100 项的 `edits` 批量输入。它读取现有 UTF-8 文件后，对每个 `oldText` 针对同一份原始内容进行严格、区分大小写的字面量匹配，不使用正则表达式，也不做相似度或模糊匹配。每个 `oldText` 必须恰好出现一次，匹配区间必须互不重叠；所有检查通过后才会一次性提交整个批次。

零匹配返回 `EDIT_NOT_FOUND`，多匹配返回 `EDIT_NOT_UNIQUE`，重叠返回 `EDIT_OVERLAP`，任一失败都不会写文件。所有编辑输入（每项 `oldText` 与 `newText` 的 UTF-8 字节总数）和替换后的结果内容分别限制为 1,048,576 字节。这个约束让模型必须先读取上下文，再提供足够明确的原文，而不是让 Runtime 静默选择某一个位置。

## 同一路径按顺序修改

AI SDK 可能并发执行同一步里的多个工具调用。不同文件可以各自写入，但规范化后指向同一路径的操作会进入同一条等待队列，包括 `same.txt` 与 `./same.txt` 这样的等价写法。

锁只覆盖一次完整的读取、验证和原子替换。排队期间收到取消信号的调用在取得执行权后会立即返回 `CANCELLED`，不会覆盖前一个调用刚写好的结果。队列在操作成功或失败后都会释放，也不会长期保存已经空闲的路径。

现有的 Runtime tool lifecycle events 没有改变。CLI 继续显示工具名、包含目标路径的输入摘要，以及 `bytesWritten`、`created` 或 `replacements` 结果。可复制的离线演示现在会运行全部六个工作区工具：

```bash
pnpm agent:workspace-tools-demo
```

演示使用 `MockLanguageModelV3` 先查看临时工作区，再创建并精确修改一个文件。它不需要模型凭据，也不会发起网络请求。
