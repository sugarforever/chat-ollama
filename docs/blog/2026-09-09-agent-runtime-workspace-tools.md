---
title: ChatOllama Agent Runtime 的工作区读取工具
date: 2026-09-09
---

`ChatOllama Agent Runtime` 已经有了可以连续调用工具的 Agent Loop，但此前能调用的只有一个确定性时钟。模型知道怎样发起工具调用，却还不能查看启动目录里的代码和文档。

这次我补上 `read_file`、`list_directory`、`grep` 和 `find_files`，让 Runtime 获得一组最小的只读工作区能力。这篇开发笔记会梳理路径边界、搜索进程、输出限制与取消怎样落到实现和测试里。期望对大家有所帮助。

## 工作区先于工具

四个工具共享的核心并不是文件系统 API，而是 workspace root。CLI 启动时把当前目录传给 Runtime，一个 Session 在整个生命周期里只使用这个根目录。

模型提供的路径只能是相对路径。Runtime 先拒绝绝对路径，再把相对路径解析到 workspace root 下，检查词法结果是否仍在根目录内。这里不能只写一个字符串前缀判断：`/work/app-other` 以 `/work/app` 开头，但显然不是它的子目录。实现会要求目标等于根目录，或者以“根目录 + 路径分隔符”开头。

词法检查还不够。工作区里的符号链接可能指向外部文件，所以 Runtime 会继续取得目标的真实路径，再做一次同样的边界判断。这样可以同时挡住 `..`、绝对路径、相邻目录前缀混淆和符号链接逃逸。

测试没有只覆盖一个 `../secret.txt`。它会临时创建外部目录、名字相似的相邻目录，以及指向外部文件的符号链接，然后通过真实工具入口逐项验证固定的 `PATH_OUTSIDE_WORKSPACE` 结果。

## 搜索不是 shell

`grep` 和 `find_files` 复用机器上的 `ripgrep`，但模型没有机会拼接命令行。Runtime 固定选择 `rg` 可执行文件，用字符串数组传递参数，并明确设置 `shell: false`。

搜索文本和 glob 都只是数组里的单个元素。`--` 把搜索文本与选项分开，因此像 `needle; touch /tmp/injected` 这样的内容不会获得 shell 语义，也不能变成额外参数。

这部分除了真实搜索测试，还有一个很窄的进程替身。测试直接检查可执行文件名、argv 数组、`--` 分隔符和 `shell: false`，也验证取消时子进程会收到终止信号。替身只观察 Runtime 与进程的边界，不替代真实 `rg` 的结果测试。

## 有界输出

Agent 工具不能把任意大小的文件或搜索结果放进上下文。四个工具都把 65,536 字节作为输出硬上限，并增加更直观的数量限制：`read_file` 最多 2,000 行，`list_directory` 最多 1,000 项，`grep` 最多 100 个匹配，`find_files` 最多 1,000 个文件。

成功结果总会带上 `truncated`。它为 `true` 时，结果里会同时返回对应限制；`read_file` 还会在文本末尾加入明确的截断标记。UTF-8 文本按字符边界裁切，不会为了凑字节数产生替换字符。

预期内的失败也不抛出机器路径或底层错误。缺失路径、不支持的类型、无效 UTF-8、越界、取消和搜索失败都有稳定的 code 与 message。模型可以根据 code 调整下一次调用，CLI 仍然只呈现 Runtime 已有的 tool lifecycle events。

## 取消贯穿同一条链路

Session 原本已经用 `AbortController` 管理一次 run。AI SDK 会把同一个 signal 传给工具执行函数，所以文件工具可以在开始、读取完成和遍历过程中检查取消；搜索工具则在取消时终止 `rg` 子进程，并返回 `CANCELLED`。

这保持了原来的职责划分：Runtime 拥有取消与事件，CLI 只负责响应 Ctrl+C 和展示状态。实现没有增加审批系统，也没有引入通用沙箱抽象，因为只读文件工具并不需要提前承担任意代码执行的安全问题。

仓库提供了一条不需要模型凭据的演示命令：

```bash
pnpm agent:workspace-tools-demo
```

它会创建临时工作区，让 `MockLanguageModelV3` 在一次真实 Tool Loop 里依次读取文件、列目录、搜索内容和查找文件，再把结果交给下一步模型响应。演示与自动测试走的是同一套 Runtime 和 CLI 代码，执行完后临时目录会被清理。
